# BaobabWildlifeRehab

A C# Windows Forms application for a fictional rehabilitaion centre **Baobab Ridge Wildlife Rehabilitation Centre**. It records every animal in care, calculates its status and housing unit from the vet's Recovery Score, and produces a summary report for the Centre manager. All data is stored in plain text files.

## How to Build and Run

**Requirements**
- Windows
- Visual Studio 2022 (or newer) with the **.NET desktop development** workload
- .NET 8.0 SDK or newer

**Steps**
1. Clone the repository:
   ```bash
   git clone https://github.com/AnruvonLudwig/BaobabWildlifeRehab.git
   cd BaobabWildlifeRehab
   ```
2. Open the `.sln` file in Visual Studio.
3. Run the project.

`animals.txt` is set to **Copy if newer**, so the starter data is copied beside the `.exe` automatically on every build. No manual file setup is needed.

## Features

1. **Add** – Enter Animal ID, Name, Species, Age and Recovery Score. Every field is validated, the status and housing unit are calculated, and one new line is appended to `animals.txt`. The calculated status and housing unit are shown to the user.
2. **View** – All valid records are loaded from `animals.txt` into a read-only grid in file order. The grid refreshes automatically after every add, update and delete. Malformed lines are skipped with a message showing how many.
3. **Update** – Load an animal by clicking a grid row or by searching for its Animal ID. The ID is locked while editing. Saving applies the same validation as Add and recalculates the status and housing unit and updates the record in `animals.txt`.
4. **Delete** – Select a row and confirm with a Yes/No prompt showing the animal's ID and name on yes that record is removed from `animals.txt`.
5. **Summary Report** – Shows the total number of animals, average age, average recovery score and the count per status on the form, and saves them to `summary.txt`. If there are no animals, the counts are 0 and both averages show `N/A`.

| 20–39 | Serious | High-Dependency Ward |

## Project Structure

The project follows a three-layer architecture. Each layer only talks to the layer below it.

| Folder | Layer | Responsibility |
|---|---|---|
| `Presentation` | Presentation | The user interface. It shows data and messages and handles button clicks only. |
| `BusinessLogic` | Business | Validation rules, classification and the summary calculations. |
| `Data` | Data | Reading and writing the text files and handling file errors. |
| `Models` | Shared | The `Animal` and `SummaryReport` classes. |

## File Formats

Both files are stored in the same folder as the running `.exe`.

### `animals.txt`

One animal per line, with 7 fields separated by the pipe character `|`:

```
ID|Name|Species|Age|Score|Status|Housing Unit
```

Example:
```
WR-0002|Naledi|Serval|3|62|Recovering|Outdoor Enclosure
```

- UTF-8 encoding, no header line and no blank lines.
- IDs are `WR-` followed by exactly 4 digits and are saved in upper case.
- Name and Species cannot contain the `|` character.
- Malformed lines (wrong number of fields, non-numeric age or score, or an invalid ID) are skipped when loading.

### `summary.txt`

A text report that is **overwritten** every time the summary is generated. It contains the centre heading, a `Generated: yyyy-MM-dd HH:mm` timestamp, the total number of animals, the average age and average recovery score, and the count for each of the five statuses. All five statuses are always listed, including those with a count of 0. This file is generated by the program and is not committed to Git.

## Known Limitations

- Malformed lines are skipped when loading and are **not preserved**. They are removed from `animals.txt` the next time the file is rewritten by an update or delete.
- An Animal ID cannot be changed after the animal is saved. To correct an ID, delete the animal and add it again.
- The application is designed for a single user on one computer. It does not handle two people editing `animals.txt` at the same time.
- The data lives only in `animals.txt`, so there is no automatic backup or undo for deleted records.
